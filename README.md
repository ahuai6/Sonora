## 直接使用

运行 `Sonora-1.3.3-Windows-x64.exe` 即可，无需安装 Node.js 或另外启动接口服务器。适用于 Windows 10 / 11 x64。免安装程序首次启动会解压运行文件，配置默认存放在 `%APPDATA%\Sonora`，下载默认保存到系统音乐目录下的 `Sonora` 文件夹。

1. 在顶部输入关键词，按 Enter 聚合搜索；可分别选择网易云、QQ、酷狗以及歌曲、歌手、专辑、歌单。
2. 点击歌曲名称或行前播放按钮试听；底部提供进度、音量、循环模式、队列和期望音质。
3. 在偏好与音源中选择下载目录、并发数、歌词保存方式与默认音质。歌曲支持单首、勾选下载、本页批量下载。
4. 歌词搜索可独立检索候选歌曲、预览原文 / 翻译 / 罗马音并另存逐行 / 逐字增强 LRC 或 TTML；无对应歌词时明确显示原因。
5. 在平台账号中使用 App 扫码、官方网页登录或 Cookie 导入。可保存多个账号并切换当前账号，读取自己的歌单。昵称和用户 ID 可单独修改。
6. 本地音乐可导入文件或递归扫描文件夹，读取音频元数据，支持筛选、排序、收藏、试听、显示文件、移除库记录和移入回收站。

空格播放 / 暂停，Ctrl+F 聚焦顶部搜索，Esc 关闭弹窗。输入框、按钮、菜单及弹窗内保留原生键盘行为。

## 音源与实际边界

- 内置网易云、QQ、酷狗接口引擎；网易云、QQ、酷狗歌曲搜索、推荐歌单、榜单，以及可访问样本的音频播放已做实时测试。
- QQ 完整歌单搜索可能要求有效登录态；匿名歌手 / 专辑搜索必要时从匹配歌曲提取关联结果，界面会说明列表可能不完整。歌手展开在直连失败时使用匹配歌曲作为备用。
- 账号登录能力已实现，三个平台的二维码生成已验证；未使用真实个人账号代登录，因此个人歌单和会员权益需要使用者登录后实际验证。
- 高音质和完整音频依赖平台权限、地域与上游支持。音质选择是期望值；公共备用服务不一定返回请求音质。不会进行音频转码，也不处理 QMC、MFLAC 等专有加密音频。
- 酷狗内置引擎默认使用标准版协议，概念版账号 Token 不一定通用。需要其他协议时可接入自己的兼容 API。
- 试听片段可播放；下载时检测显式试听标记，并在可读取时长时检查是否明显短于歌曲，避免将片段当完整曲目保存。此检查不能替代对未知音源版本的人工核对。
- 暂停 / 重试会重新取链并从头下载，不提供断点续传。关闭应用后运行中的任务下次以暂停状态恢复。
- 下载进入“保存文件”提交阶段后暂不可取消或移除，避免已经落盘的文件与任务状态不一致。
- 公共服务可能失效。失败会显示平台、错误原因，不用样例内容冒充实际音乐。

## 更换接口

在「偏好与音源」填写兼容 API 的基础地址并保存，或展开「高级：路由与字段映射」编辑 JSON，立即生效。默认使用内置引擎，基础地址留空即可恢复。运行时覆盖文件为 `%APPDATA%\Sonora\providers.json`；源码默认文件为 `profiles/providers.json`。

配置支持 GET / POST、参数模板、候选列表 JSON 路径、歌曲字段映射、播放地址 / 码率 / 文件大小 / 试听标记映射、歌词字段映射，以及公共取链服务的有序回退。账号 Cookie 只发送给官方内置引擎或被明确勾选信任的自建服务，公共取链服务不会自动接收账号 Cookie。

详见 [接口维护指南](docs/接口维护指南.md)。

## 本地数据

`state.json` 保存设置、下载记录、音乐库和加密账号凭据；账号 Cookie 使用 Electron safeStorage 对接 Windows 系统加密，渲染进程只获得账号摘要。系统加密不可用时拒绝保存账号。网页登录使用独立的本地 Chromium 会话。

不要把运行时数据目录当作源码分发。诊断导出不包含账号 Cookie、账号列表、音频签名 URL 或本地音乐目录。

可通过命令行指定独立配置目录，例如：

```powershell
.\Sonora-1.3.3-Windows-x64.exe --user-data-dir="D:\SonoraData"
```

## 源码开发

使用 Node.js 24.22.1 或更新的 24.x，以及 npm 11（本版干净安装验证使用 11.21.1）。酷狗接口源代码已经放在 `vendor/kugou`，无需另行克隆。直接依赖精确锁定，完整依赖树保存在 package-lock.json。

```powershell
npm ci
npm run dev
```

生产构建与测试：

```powershell
npm run build
npm test
npm run test:e2e
npm run test:live
npm run package
```

`npm run package` 生成 `release/Sonora-1.3.3-Windows-x64.exe`。默认生成未签名的免安装版；正式分发需要自行配置代码签名证书。

## 代码结构

```text
src/                    React 界面、播放器、歌词与账号交互
main/app.mjs            窗口、受限 IPC、原生文件对话框
main/core/              统一资源模型、参数模板、HTTP、加密存储
main/providers/         引擎桥接、平台能力、回退与解析
main/services/          下载队列、音频校验、媒体协议、本地音乐库
profiles/providers.json 可替换的默认接口配置
vendor/kugou/           固定提交的酷狗接口引擎源代码
tests/                  核心测试和桌面端流程测试
docs/                   使用边界、接口扩展与验证记录
```

推送与包版本相同的标签（例如 `v1.3.3`）会触发 `.github/workflows/release.yml`，Windows 构建与打包桌面回归成功后直接将 EXE 和 SHA256 上传至 GitHub Releases。手动运行可另外尝试保存 Actions 产物，保留 3 天；该可选上传失败不影响 Release 发布。main 推送及 PR 另外运行核心测试、构建、依赖审计与桌面回归。
